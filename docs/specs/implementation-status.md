## ما يعمل فعليًا محليًا

- طلب تجربة محفوظ في D1، ثم تهيئة مجموعة وربط حساب قائد محدد بها بواسطة مشغل المنصة. مشغل المنصة لا يملك تفاصيل المجموعة تلقائيًا.
- API محمي بهوية الاستضافة، وعزل المجموعات على الخادم. ملف تشغيل محلي يمنح هوية التطوير فقط إدارة المنصة؛ لا يدخل ضمن ترحيلات النشر.
- تكليفات متعددة وأدوار محدودة بالوحدة، وقائد قطاع يرى الفرق التابعة. تفويض مسجل بصلاحيات ونطاق ونهاية وإلغاء، دون استبدال توقيعات المعتمدين. التعيين الكامل كقائد عام إجراء مباشر للقائد العام الحالي؛ التفويض الإداري وحده لا يسمح بإنشاء قيادة عامة.
- إنشاء السنوات والقطاعات والفرق والطلائع، والتحقق من تسلسل الوحدات وتواريخ السنوات. فصل سجل الشخص عن سجل عضويته السنوية في الإنشاء الجديد عند إعداد السنوات. نقل العضوية والتجديد لم يكتملا.
- طلب فرد، بدء المقابلة/التجربة، وقرارات الكاهن والقائد العام. الاختلاف يدخل المناقشة؛ الاتفاق ينتج قبولًا أو رفضًا. تاريخ التجربة لا يحذف.
- تقديم واقعة تاريخية بدقة يوم/سنة/تقريب مع المصدر؛ اعتمادها يحتاج السكرتارية المكلفة. واجهة الفرد /me تعرض ملفه وحده بعد ربط حسابه، وتسمح بتقديم التاريخ للسكرتارية؛ رفع ملفات الشهادات لم يكتمل.
- خطط عامة وقطاعات وفرق مرتبطة بالمستوى الأعلى؛ مسار اعتماد قابل للضبط، وحفظ قائمة المعتمدين عند الإرسال. كل قرار يحتاج صاحبه وتكليفه الحالي.
- إصدار جديد للخطة بلا توقيعات موروثة، مع الاحتفاظ بالنسخة السابقة؛ المصروف عبر الإصدارات يشترك في سقف واحد، فلا تعيد النسخة فتح الميزانية المصروفة.
- اجتماع تحت خطة معتمدة، حضور وتقييم مستقلان، تقرير المخطط والمنفذ، وتسجيل الأحداث في أرشيف الفرد.
- إشعارات داخل التطبيق لطلبات الخطط والمصروفات ومراجعة التاريخ ونتائجها، مع إعداد إيقاف كل نوع للمستخدم وتحديد الإشعار كمقروء. إشعارات الفرد لا تعرض بيانات فرد آخر.
- ملف manifest للإضافة للشاشة الرئيسية وخدمة عامل ذات صفحة انقطاع عامة فقط؛ لا تخزّن بيانات API أو HTML الحسابات. تثبيت جهاز فعلي لم يختبر.
- صندوق مركزي وصناديق وحدات وأمين معين لكل صندوق، وتحويل داخلي واحد لا يحتسب إيرادًا جديدًا، ومساهمات اختيارية وصرف فعلي داخل ميزانية معتمدة، مبالغ صحيحة بالقروش، منع تجاوز النقدية والميزانية، وسجل عمليات.
- طلب مصروف مستقل خارج الميزانية: اعتماد المسؤول وأمين الصندوق معًا حسب نطاق الصندوق، ثم تسجيل الدفع الفعلي مرة واحدة. الاعتماد لا يخصم النقدية قبل الدفع.
- منع تكرار الأوامر، وتحديث مشروط بإصدار السجل، ورفض التعارض بدل الكتابة الصامتة فوق تعديل آخر.
